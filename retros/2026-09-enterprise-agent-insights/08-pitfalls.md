---
title: 踩坑汇总
---

- **[模块5]** 提示词里写了"遇到 X 就追问 / 非 Y 业务就兜底"，AI 变成二分法，中间的正常回答被压缩 → 反例和兜底在模型注意力里权重偏高，关键词一出现就触发 → 正面引导优先："遇到 X 情况，按 Y 处理"；兜底话术不与业务关键词绑定
- **[模块5]** 知识库加了"什么不属于零用金"的排除性知识，原本能识别的场景也开始犹豫 → 排除性知识更隐蔽、更难定位，检索命中后会悄悄拉偏判断 → 知识库只写"是什么"；确需边界说明时单独成条并标注为边界
- **[模块5]** 兜底方案没设触发门槛，AI 把它当安全出口大量调用 → 兜底路径比思考路径"便宜"，模型会躲懒 → 兜底必须设门槛，例如"尝试 A / B / C 路径均失败后才启用"
- **[模块6]** 表格型知识库默认上了 RAG，表格被语义切片切碎 → 检索技术没按文档形式选型 → 先看知识长什么样：表格用按页索引，长文本才用语义切片
- **[模块1]** 只给了业务知识没给边界知识，AI 对"个人法律问题"时答时拒 → 没有"什么算公司法律业务"的正面定义，无法稳定判定界外 → 边界知识作为独立知识条目补齐，用正面定义写
- **[模块2]** 把多模态单据识别当成稳定能力承诺给了业务方 → 识别结果有波动，它是边缘区能力 → 承诺改为"尽力识别 + 失败时正确降级"，验收同时看成功率和降级正确性
- **[模块6]** 思考模式和多模态默认全开，回答慢到 30 秒以上 → 每次请求都走了不必要的模型环节 → 思考按场景开关、多模态做成 Tool 按需调用、无需模型的环节从流程里拆出去
- **[模块8]** 长等待只有一个转圈 loading，用户不知道发生了什么 → UI-SPEC 没定义中间态 → 中间态展示当前处理阶段（"正在检索相关政策"），写进交付物
