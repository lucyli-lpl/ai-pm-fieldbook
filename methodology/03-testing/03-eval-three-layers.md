## 评测分三层（判定方式不同 → 能测的问题种类不同）

评测按"谁来判、判起来多贵"分三层，三者不是能力递增、可互相替代，而是各测各的、组合起来才完整：

| | 判定主体 | 能测什么 | 成本 / 规模 | 使用节奏 |
|---|---|---|---|---|
| L1 断言测试 | 代码断言 | 只能测**客观可判定属性**（格式、数量、越权、字段、是否命中枚举、应触发的动作） | 便宜、可批量 | 每次代码/prompt 改动都跑 |
| L2 人工 + 模型评测 | 人 / LLM | 能测**需判断的语义质量**（专业性、诚实降级、动作是否恰当、话术） | 贵、量受限、需精心设计 | 定期跑 |
| L3 A/B 测试 | 真实用户行为 | 能测**真实因果**（用户是否真受益） | 最贵、需生产数据 | 重大产品变更后 |

分层本质：用便宜快速的检查挡住大部分问题，只把真正需要判断的留给上层。能断言的走 L1，要判断的走 L2，要看真实受益的走 L3。

**关于 L3 的定位**（避免误解）：L1/L2 测「AI 答得对不对、好不好」，L3 测「AI 是否真的驱动了想要的用户行为和业务结果」——这是从「输出质量」到「真实影响」的跨越。三点判断：
- L3 是**通用产品/数据技能**（分流、对照组、统计显著性），不是 AI 特有难点，无需在 AI 评测里另起炉灶；
- L3 天然**后置**：前提是 L1/L2 已把质量保证到一定水平，否则 A/B 测出的差异被 bug 污染；且需真实流量和足够样本，冷启动阶段用不上；
- **但 L3 的前提——「能衡量真实结果的埋点」——必须上线时就埋好**，否则将来无数据可比。

## 断言（断言测试 L1 的原子）

- 断言 = 对输出的**某个可被代码自动判定真假的属性**做检查；成立即过，不成立即报错。
- 断言测的是「必须成立的客观条件（可接受行为的边界）」，**不是**「文本等于某个标准答案」——自然语言换个说法就会误伤，几乎从不 assert 文本相等。
- 断言优先作用在**结构化字段**（如 flowId、templateId、agentId、downloadState），而非模型的自然语言原文。

**PM 的高价值动作：把一条产品要求里「能客观判定的骨头」抽出来交给 L1，把「需要体会语义的肉」留给 L2。**
例：「无权限时礼貌告知但不给链接」——「不给链接」可断言（link 字段为空 / 输出不含 URL），归 L1 硬兜住；「礼不礼貌」需判断，归 L2。

## 断言测试（L1）落地三步

**① 按 feature → scenario 拆，每个场景配断言**
- 把能力拆成 feature，再按「结果形态」把每个 feature 拆成 scenario，逐一配断言。
- 断言分三类，必须成对/成组设计，不能只写正样本：
  - **正样本（召回）**：典型提问 → 期望命中正确资源（如 flowId == 正确流程）。测「该命中的有没有命中」。
  - **负样本（精度）**：断定「不该发生的一定不发生」。两种形态——① 同一道题对「别的流程」断言不被误触发（与正样本共用题目、不同视角）；② 纯界外题，断言 flowId/templateId/agentId 全为空（独立题目）。测「不该命中的有没有被误命中」。
  - **边界样本（劈成两半）**：模糊/多候选提问 → L1 只断言「有没有触发正确动作」（action == clarify / fallback，可判定）；动作的**质量**（问得好不好、是否问决定性信息）归 L2。L1 守底线「没乱猜」，L2 磨质量「问得好」。
- 另设**通用断言**（不绑定 feature，全局都必须成立）——对应方法论的 **S0 红线**，如「输出不得含内部 UUID」「无权限响应不得含链接」。S0 断言做成**发布门禁**（一票否决），不参与平均通过率。

**② 用 LLM 批量合成测试用例**
- 不必等生产数据；先合理猜测用法合成，放小批用户后再用真实用法反哺合成策略。
- **故意造难**：测试若全过，可能是题太简单；好测试的信号是模型会挂——这些失败正是后续可优化的问题。
- **配对/闭环设计**：如「创建联系人 + 回查是否恰好 1 条」，用两步互验把主观判断转成客观数量检查。
- 服务台助手的追问示例（密码重置 vs 账号解锁、VPN 申请 vs VPN 故障报修、软件安装权限 vs SaaS 账号开通等）是天然的「易混负样本」种子，可让 LLM 基于每一对批量生成混淆提问。

**③ 定期跑 + 追踪趋势**
- 用技术栈里摩擦力最小的方式跑（如 CI 每次变更触发）。
- **不能只看单次通过率，要看趋势曲线**——「这周比上周好了吗」。把测试结果连同 **prompt 版本**一起存档（存到 CI 之外便于长期分析），质量掉了能回溯是哪次改动导致。这就是「prompt 当代码管、版本化、可回归」的具体做法。
