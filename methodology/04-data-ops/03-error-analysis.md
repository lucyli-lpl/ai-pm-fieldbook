## 行为信号：推断而非确定，看趋势不看个案

行为信号（放弃、多轮未解决等）是**推断**出来的，单信号有噪声，需**证据序列组合**提纯。**行为信号看群体趋势可靠，看个体判定不可靠**。正确用法——定一个"疑似"宽松规则捞进候选池，再**抽样估比例**。

> 采样偏差警告：只看点踩样本会**高估失败率**（点踩是负向偏置样本，非随机）。

## 信号价值分级：按信号价值分配处理成本

- **高价值信号（用户明确改正、带原因的点踩）→ 人工核**；
- **海量低信息信号（行为埋点、纯点踩）→ LLM 批处理 / 聚合统计**。
- 信号权重参考排序：明确改正 > 带原因点踩 > 纯点踩 > 会话放弃。

## error analysis：运营的分析引擎

源自 Hamel/Shreya：open coding → axial coding → 理论饱和。

**四步流程：**
1. **建数据集**：收集有代表性的交互 trace。
2. **开放式编码（人做，PM/领域专家主导）**：先不看母表，忠实记录每条 trace 的**第一个失败**。
3. **轴向编码**：把零散笔记归纳成失败分类法，并**数每类频次**。
4. **迭代到理论饱和**：新 trace 不再冒新类别即停。口诀：先看满 100 条打底，之后连续约 20 条无新类别即停。

**三个关键洞察：**
- **① 起点破环**：冷启动没数据？输入可**合成**；合成的先验来自演绎资产（PRD 业务定义 + 母表假说）。但**上线/灰度真实 trace 不可替代**。
- **② 人机分工**：**A 发现类别**（创造性）**必须人做**；**B 套用类别+计数**（机械）**交 LLM**。
- **③ 演绎 × 归纳互补**：母表是演绎假说，error analysis 用真实数据归纳校准。

**嵌入两轮测试的完整流程：**
```
[冷启动·第一轮：探索，产出校准后的母表]
1 建数据集：PRD 语料 + 母表指导 → 合成刁钻输入 → 喂系统 → 合成 trace
2 开放式编码（人）：先不看母表，记录每条 trace 第一个失败
3 轴向编码：A 发现类别（人）B 套用+计数（LLM）
4 迭代到饱和
   → 产出：母表 v+1 + 每类频次/优先级 + 稳定分类标准
[第二轮：正式测试，用校准后母表测达标]
[上线后：点踩 trace 优先采样 → 持续 error analysis → 母表持续进化]
```

## 归因与派单

- **归因靠基础设施，不靠拍脑袋**：走错门→查 router；答不全→查知识库/生成；人设崩→查 system prompt。
- **归因决定派单**：归因维度是运营与研发的接口——归因打对，badcase 才自动流到对的人。
- **高频边缘 → 迁核心**：运营最有产品价值的产出。
- 归因只在实际表现不达标后进行，**不把未经验证的推测写回能力边界**。

## 隐私与数据治理

反馈系统一开始就要定清隐私规则：谁能看原始对话、数据留存多久、哪些要脱敏。**聚合信号只有在采集政策对负责人清晰可读时才有用。**
